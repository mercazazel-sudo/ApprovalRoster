# Approval Roster

Шкалы одобрения компаньонов для ролевых чатов в [SillyTavern](https://github.com/SillyTavern/SillyTavern).

Approval Roster отслеживает отношение выбранных компаньонов к действиям персоны игрока. После ответа персонажа отдельная модель-судья анализирует сцену и назначает каждому присутствующему компаньону изменение **−1**, **0** или **+1**.

Это система одобрения и доверия, а не автоматический счётчик романтики.

## Возможности

- отдельный перетаскиваемый виджет со шкалами от `−100` до `100`;
- сворачивание виджета в компактную кнопку с сохранением состояния;
- индивидуальный список компаньонов для каждого чата;
- ручные статусы: нейтрал, платоника, дружба, любовь, семья и вражда;
- отдельные списки поступков, которые компаньон одобряет и не одобряет;
- определение присутствия по имени и дополнительным текстовым крючкам;
- собственное OpenAI-совместимое API-подключение для модели-судьи;
- загрузка списка доступных моделей через endpoint `/models`;
- защита от всеведения: поступок учитывается только для свидетелей или тех, кому о нём рассказали;
- автоматический откат оценки при удалении сообщения, регенерации или смене свайпа;
- ручная повторная оценка последнего хода;
- хранение ростера и очков в метаданных текущего чата.

## Требования

- актуальная версия SillyTavern;
- OpenAI-совместимый endpoint с поддержкой `/chat/completions`;
- модель, способная возвращать валидный JSON;
- для внешнего API может потребоваться `enableCorsProxy: true` в `config.yaml` SillyTavern.

Расширение не требует npm-пакетов и отдельной сборки.

## Установка

### Через SillyTavern

1. Откройте **Расширения** → **Установить расширение**.
2. Вставьте URL:

   ```text
   https://github.com/mercazazel-sudo/ApprovalRoster
   ```

3. Подтвердите установку и перезагрузите SillyTavern.

### Вручную

Скопируйте содержимое репозитория в:

```text
SillyTavern/public/scripts/extensions/third-party/ApprovalRoster
```

Итоговая структура должна выглядеть так:

```text
ApprovalRoster/
├── manifest.json
├── index.js
├── config.js
├── judge.js
├── ui.js
└── style.css
```

После копирования перезагрузите страницу SillyTavern.

## Быстрый старт

1. Откройте **Расширения** → **Approval Roster** → **Открыть окно**.
2. Перейдите на вкладку **Настройки**.
3. Укажите:
   - базовый API URL, например `https://api.openai.com/v1`;
   - API-ключ, если он требуется провайдером;
   - идентификатор модели;
   - число сообщений контекста.
4. На вкладке **Компаньоны** добавьте участников сцены.
5. Для каждого компаньона заполните имя, крючки присутствия и списки предпочтений.
6. Продолжайте чат. После ответа ассистента судья обновит шкалы.

Окно также открывается через пункт **Approval Roster** в меню волшебной палочки над полем ввода.

## Настройка компаньона

### Имя в тексте

Точное имя, которым модель называет компаньона в сцене.

### Крючки

Дополнительные варианты имени или устойчивые обозначения, разделённые запятыми, точками с запятой либо переносами строк.

Пример:

```text
Astarion, Астарион, бледный эльф, вампир
```

Совпадение имени или крючка делает компаньона кандидатом для оценки. Судья всё равно должен определить, видел ли он поступок или узнал о нём.

### Заметка для судьи

Короткое описание личности и ценностей. Не стоит копировать сюда всю карточку персонажа: длинный контекст дороже и обычно судит хуже.

### Одобряет / Не одобряет

Один принцип или тип поступка на строку.

```text
защищает слабых
уважает личную свободу
не выдаёт секреты союзников
```

### Очки и статус

Очки изменяются автоматически в пределах `−100…100`, но их можно исправить вручную. Статус отношений всегда задаётся вручную и не меняется судьёй.

## Как работает оценка

1. Расширение ждёт новый ответ ассистента.
2. Ищет в последнем смысловом фрагменте имена и крючки компаньонов.
3. Передаёт отдельной модели-судье контекст сцены и настройки найденных кандидатов.
4. Принимает JSON следующего вида:

```json
{
  "deltas": [
    {
      "name": "ExactName",
      "delta": 1,
      "reason": "short phrase"
    }
  ]
}
```

5. Нормализует любое изменение до `−1`, `0` или `+1`.
6. Сохраняет новые значения в метаданных чата.

Если никто из ростера не найден в текущем фрагменте, API-вызов не выполняется.

## Данные и приватность

- Ростер, очки, журнал и снимки отката сохраняются в метаданных текущего чата.
- API URL, ключ, модель и промпт судьи сохраняются в настройках расширения SillyTavern.
- Фрагменты ролевого чата отправляются выбранному пользователем API-провайдеру.
- Расширение не отправляет данные разработчику.

Не публикуйте `settings.json`, экспорт настроек или скриншоты с видимым API-ключом.

## Совместимые API

Провайдер должен реализовывать OpenAI-совместимые endpoints:

```text
GET  /models
POST /chat/completions
```

Если провайдер не поддерживает `response_format: { "type": "json_object" }`, расширение автоматически повторит запрос без этого параметра.

## Диагностика

### `CORS. В config.yaml включи enableCorsProxy: true`

Включите CORS proxy в конфигурации SillyTavern и перезапустите сервер.

### `Нет API URL судьи`

Откройте вкладку **Настройки** и укажите базовый URL провайдера.

### `Укажи модель судьи`

Введите идентификатор модели вручную или нажмите **Список**.

### `Не JSON от судьи`

Используйте модель, которая надёжно следует формату JSON. При необходимости уточните промпт судьи.

### Оценка не меняется

Проверьте:

- включён ли судья;
- совпадает ли имя или один из крючков с текстом сцены;
- присутствовал ли компаньон при поступке;
- заполнены ли списки «Одобряет» и «Не одобряет»;
- не вернул ли судья обоснованный `0`.

## Обновление

До настройки автоматических обновлений замените файлы расширения новой версией и выполните полную перезагрузку страницы.

Настройки и данные чатов при замене файлов не удаляются.

## Ограничения

- интерфейс расширения сейчас русскоязычный;
- присутствие определяется текстовым совпадением имени или крючка;
- качество оценки зависит от выбранной модели и описания компаньонов;
- API-ключ хранится в настройках SillyTavern на стороне пользователя;
- автоматическая смена статуса отношений намеренно не реализована.
